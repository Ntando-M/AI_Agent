AI Data Analyst — V10 Architecture

Three front doors, one engine · Python CLI + FastAPI + ASP.NET Core gateway · LangChain · Pandas/SQLite · Chroma RAG · Groq or Ollama — derived from source at HEAD 07c7f2d plus the uncommitted working tree

Three front doors, one engine

  • • main.py CLI: interactive loop, provider and session selection, /history /clear /exit
  • • api/app.py FastAPI: 16 routes over sessions, chat, analyse, datasets, documents, reports
  • • api-dotnet/ ASP.NET Core gateway (:5000): proxies 16 routes to FastAPI and holds the X-API-Key server-side, so the Angular bundle never carries it
  • • All three build LLMGateway.build(provider) and inject it into the same Orchestrator
  • • All three persist through the same SQLiteConversationStore
  • • /health is deliberately unauthenticated; every other route needs the key

Deterministic core

  • • orchestrator/intent.py → SourcePlan: documents / dataset / database / chart, multi-source
  • • Orchestrator.handle() merges retrieval and analysis, then reconciles claimed sources against what actually ran
  • • Generated artefacts (charts, reports) are stripped from sources
  • • 19 tools: 15 Pandas + 4 read-only SQL, each with a Pydantic input model
  • • The LLM plans and phrases; Pandas and SQLite compute

State and stores

  • • memory/sqlite_store.py: ConversationStore ABC + SQLite implementation
  • • chat_history.db holds message_store and the session catalog, so an empty created session is still listable
  • • data/sample_sales.xlsx working dataset; data/sales.db optional analytics DB
  • • chroma_db/ optional vector index — the API degrades to documents_indexed: false without it
  • • outputs/charts/ holds generated PNGs; reports/ (V10) holds one JSON file per report — persisted, not in-memory
  • • data/uploads/ and documents/ are the only upload targets
